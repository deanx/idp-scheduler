## DoD (h): the exit condition is un-closeable, and the gate's definition is the defect

`gitleaks git .` scans **full history**, so a working-tree rename cannot clean the old literal at `353549d`. Working tree/staged: clean. Full history: 1 hit. Atchim's ruling, unchanged across two passes: **T-01.4.10 leg 1's blocking-full-history definition is itself the defect**, on four counts — its verdict is a function of the past rather than the change under review; any historical finding is permanently un-closeable except by rewriting published history (*"a control whose only remedy is a destructive operation is not a control"*); it is O(history) on every PR; and it conflates *"does this PR introduce a secret"* (blocking, diff-scoped) with *"does history contain one"* (periodic audit, whose correct response is **rotation**, not a red build). It was chosen on 2026-09-20 while history was clean — precisely when the flaw is invisible.
**Recommended shape:** merge-base-scoped blocking gate (`gitleaks git --log-opts="$(git merge-base origin/main HEAD)..HEAD"`) + `gitleaks protect --staged` at pre-commit + a **separate, non-blocking scheduled full-history audit** with a triaged baseline. A **fingerprint**-keyed allowlist entry for `353549d:tests/platform/test_langfuse_adapter.py:generic-api-key:305` is explicitly ruled **not** within the card's prohibition — it pins one commit × file × line × rule and cannot blind any future commit, unlike the forbidden `paths = ['tests/']`. Squash-merge is a side effect of a merge mode, **not a control** — it does not hold under a cherry-pick, a fork, or a clone that already has `353549d`. **No history rewriting.** The value is verified **not a credential** (matches no live `.env` value; `.env` gitignored and untracked), so this is gate design, not a security incident.

## Findings from the independent coverage audit — both ruled debt, neither gates

**N-1 — DEBT-35's defect class was relocated, not eliminated.** `test_schema_provisioning.py:88` carries `assert body["expectedOutputSchema"]  # never empty/null` — the same dead truthy-only pattern DoD (c) deleted at `:38`, surviving verbatim in a sibling test three tests down. **Ruling: DoD (c) is legitimately closed; the class is not.** It does not create a false green (it sits among live assertions — `len(client.calls) == 2`, method/path checks, the never-DELETE check — so breaking provisioning still goes red), the bullet named `:38` and only `:38`, and *"the moment a closed DoD bullet can be reopened by intent-archaeology, no bullet is ever reliably closed and the whole ratchet stops meaning anything."* → **DEBT-42**. **The generalisable lesson, worth more than the fix: DEBT-35 was carded by LINE NUMBER, which is exactly why the twin survived — a line-scoped card cannot see a copy three tests down. Card dead-assertion debt by grep pattern (`assert <subscript>` with no comparison operator), not by line.**

**N-2 — the `__required_keys__` parametrize is 2-of-3 load-bearing.** Under MB, the `scores` leg still passes — rescued by the downstream `not isinstance(scores, list)` guard at `:117-124`, not by the key loop it exists to pin. **Ruling: not a gate.** MB is still killed twice over, and the "type-driven, not a hand-list in disguise" property is a claim about how cases are *generated*, which is untouched. **The real risk is forward-looking:** a fourth required key whose absence happens to be caught by a downstream type guard will auto-generate a leg that passes green **without observing the key loop** — DEBT-34's defect class arriving through the front door of the mechanism built to prevent hand-enumeration. Recorded as a checkable obligation in REG-09's MB note: **when a fourth key lands, re-run MB and confirm its leg goes red.**

**Two docstring-accuracy defects (→ DEBT-42, same card):** the R-1 test's docstring at `:770-779` still justifies the widened fixture by `PYTHONHASHSEED` nondeterminism, which S-1's `sorted()` already removed — and the conclusion actually *inverts* under `sorted()` (a narrow fixture would fail deterministically, not intermittently). The pin is `assert "not a dict" in message`; the fixture is defence-in-depth. And `:684`'s "auto-generates its own case here" risks being read as "auto-generates a working pin" — it generates the *case*; the hand-written `full_record` then fails loud until a human supplies a value. **S-2 (auto-synthesising that value) was correctly skipped and must NOT land: a synthesised value would guess the new field's valid shape, and a test that silently adapts to a schema change is a pin that has stopped pinning. Fail-loud is the feature.**
