## Rigor: decided, and what it buys — which is less than it sounds

**`prototype` stands (user, 2026-09-25).** Recorded here rather than silently applied, per the
standing rule in `CLAUDE.md ## Rigor`.

**The part that matters for this burn-down:** DEBT-55's draft matrix — written, complete, ready to
adopt — defines `prototype` *by what changes per path*, and on this backlog almost nothing changes:

| Path in the matrix | Under `prototype` | Which lanes that is |
|---|---|---|
| **Verdict path** (`classifier/gate.py`'s `overall_gate`, `platform/scoring.py`'s gate value) | **runs at `full` anyway** — fresh-instance stamp with a mutation matrix | Lane A's core, part of Lane C |
| **Wire-contract path** (`adapter/` correctness depending on an external API shape) | **SR-1 binds** — verified against a recorded live response, never a parser-authored fixture | Lane B, all of it |
| **Any fix round touching `src/`** | **never qualifies for `re-gate skipped`, at any profile** | **A, B, C, D, F — entirely** |
| Reviewer passes on **docs/tests-only** deltas | **one pass instead of two** | Lane E, Lane G's audit, Wave 3's doc rows |
| Mechanical floor (tests pass, mypy, ruff, secret scan) | **always** | every lane |
| `Risk: high` → `/test` stamp · DEBT-44 instance independence · NFR-01 `Containment`/`Observability` | **always** — read from the SPEC header and the NFR file, **not** the profile | see below |

**So `prototype` buys exactly one thing on this plan: a single reviewer pass instead of two on
docs- and tests-only deltas.** Every row that edits `src/` — which is Lanes A, B, C, D and F —
is unaffected, because the matrix's third line says a `src/` fix round never qualifies for a
skipped re-gate at *any* profile. That line exists because F-1 was its first casualty, within
hours of the 2026-09-21 profile change.

**And the `Risk: high` carve-out is not narrow here — it is nearly total.**
`docs/specs/SPEC-01-baseline-regression.md:7` is `Risk level: high`, and **SPEC-01 is the only
spec in the repo.** `/qa`'s rigor gate reads the risk level from the SPEC header, not from the
profile, so every S-01.x story — adapter, classifier, platform, orchestration — still requires a
`/test` stamp under DEBT-44's instance-independence rule. Lanes A, B, C and D are all SPEC-01

⚠️ **The gap this exposes, which is new and belongs in the register: Epic E has no spec at all.**
The console — the one surface that spends IDP quota from an unauthenticated loopback port — has
no SPEC header for the rigor gate to read. That is not `prototype` lightening a gate; it is a
gate with nothing to read. **File it as a row in Step 0 and decide it with D1/D2**, rather than
discovering it when Lane F is stamped.

**Two consequences for sequencing, both cheap and both now:**

1. **Adopt the draft matrix as part of Step 0** (owners already assigned: Dunga + Zangado). It is

2. **If `prototype` is meant to make *this* backlog materially cheaper, the matrix is where to

## D1 / D2: decided 2026-09-25 (user)

### D1a — `new_table` becomes the seventh verdict

An Action version that invents a table the golden does not have is gated explicitly, rather than
being invisible or folded into an existing verdict.

**Fan-out, in this order — a new verdict that reaches a score name before the registry test knows
about it is exactly the vocabulary drift INV-03 exists to prevent:**
`classifier/types.py` (the literal) → `gate.py` (`overall_gate`'s handling; note this is the
**FO-5 surface** — the fall-through that returns `"PASS"` for any unrecognised verdict, so the
seventh literal must be added to the gate's own table in the same change, not after it) →
`platform/scoring.py` → `classifier/registry.py`'s contract test (which asserts *only the six*,
by design, so a seventh is a deliberate edit) → the console's verdict rendering → ADR-0003,
CT-02/CT-03, INV-03.

**Do not ship the literal without the gate arm.** FO-5 is the fail-open that returns PASS for an
unrecognised verdict; adding a verdict the gate does not know is the precise way to convert a
caught regression into a silently-wrong GREEN build.

### D1b — table verdicts reach the platform as one score per column

`table:<name>.<column>`, matching how fields are already scored, rather than one aggregate score
per table. Finer-grained: a red on `unit_price` is legible in the platform UI without opening the
run artifact. Closes DEBT-14. Score count per run rises by the number of table columns; the score
id derivation stays the deterministic `uuid5` pattern (N26) so writes remain idempotent.

### D2a — per-column `type` in the golden schema

**The question asked was "will IDP share this information?" — it does not, and the decision does
not need it.** Verified against the committed live capture
(`tests/fixtures/live/inv-004-multipage.raw.json`): every cell IDP returns, field **and** table,
is `{"confidenceScore": 99.0, "geometry": null, "value": "108.00"}`. The value is always a
**string**, and there is no type anywhere in the response. IDP has never supplied one.

`type` is declared in the **golden**, not read from the extractor — it says what the expected
value *is*, and the classifier canonicalizes **both sides** by it. That is already exactly how
fields work, and the machinery already exists: `scripts/draft_golden.py:85` `_infer_type(name,
value)` infers `date`/`number`/`id`/`text` from the observed value and applies it to fields at
`:138`. Tables get `{match_key, critical, rows}` at `:153` and no type — **that omission is
DEBT-04 itself.**

So this is extending an existing mechanism, not building one: add `type` to the column shape in
`golden_schema_v1.json`, call the existing `_infer_type` for columns in `draft_golden.py`, and
let `calibrate_golden.py` unify it corpus-wide as it already does for fields. Absent a declared
type, a column keeps comparing as `text`, so existing goldens do not change meaning.

⚠️ **Inference is a drafting convenience, never an oracle.** `_infer_type` reads one observed
value; a `quantity` column whose first row is `"12"` infers `number` correctly and one whose
first row is `"N/A"` infers `text`. Calibration reports the unification, and the reconciliation
worklist is where a human corrects it — the same rule that already governs `match_key`.

### D2b — date format declared per field

The golden may carry a `date_format`; where it does, that format is authoritative. Where it does
not, today's behaviour stands. This closes DEBT-81 as a *decision* rather than a silent default:
`canonical.py:31` tries `%m/%d/%Y` before `%d/%m/%Y`, so every `NN/NN/YYYY` with day ≤ 12 is read
American-first, and the one fixture that exercises it (`inv-002`, `22/01/2026`) is unambiguous by
luck rather than design.

**Two obligations that travel with this choice, because the undeclared case is still a guess:**
(1) the MM/DD default must be **pinned by a test** and named in calibration's blind-spot report,
so "no declaration" reads as a known gap rather than a verified comparison; (2)
`draft_golden.py`'s inference must **not** invent a `date_format` from one observed value — a
corpus of `01/02/2024` through `05/06/2024` is indistinguishable under both readings, and a
guessed format is worse than none because it looks declared.

### DEBT-76 — not a decision, folded in as a straight fix

The schema accepts shapes the classifier rejects (`fields: {}`, `match_key: ""`), so a Curator can
save a golden that aborts the next run. Tightened alongside D2a in the same schema pass, under
CT-05's Ajv `strict: true` and the 10,000-character minified ceiling.

## Ground rules

Inherited, and each has been earned by an incident:

1. **A fix needs a failing test first.** A register row is not evidence of a defect — Step 0
   exists because six of them were wrong today.
2. **Fix the invariant, not the reported case.** Five fail-opens this week, each fix creating the
   next because it closed the repro rather than the violated property.
3. **A test must constrain the invariant, not the setup.** Seven vacuous tests found so far.
   Before adding one, know which mutation it kills, and verify that mutation.
4. **Mutation-verify every new pin:** hand-revert, confirm RED, restore byte-identical from a
   scratchpad copy (`shasum`-verified). Never `git checkout --`.
5. **After mutation testing:** `PYTHONDONTWRITEBYTECODE=1` and delete `__pycache__` — a stale
   `.pyc` from a same-second revert once made three passing tests fail against correct source.
6. **Commit your own work.** Three lanes have finished leaving work uncommitted; see Step −1.
7. **`git status` before every commit; stage explicit paths. Never `git add -A`** — DEBT-52.
8. **Report, don't absorb.** A row that is already closed, or bigger than its line suggests, comes
   back as a finding, not a silent scope change.

New, from this plan:

9. **Name the symbol, never the line** (DEBT-42's rule, violated by DEBT-83 two days after it was
   adopted). Any row or docstring citing `file.py:NNN` is filed wrong.
10. **Re-probe before any langfuse bump:** CT-05 and the three `make_platform` SDK-privates tests
    in `tests/platform/test_langfuse_adapter.py`. DEBT-75 (no upper bound in `pyproject`) makes
    this reachable by an ordinary `uv sync` on a fresh clone.
