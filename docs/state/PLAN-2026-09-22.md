## Blocked — not startable without the user

- **B-1 / B-2 (Critical).** The live Langfuse runs on the published `CHANGEME` `ENCRYPTION_KEY`
  and the default `postgres` password, bound to `0.0.0.0`, with no backup or restore drill.
  Fixing it restarts the user's instance and rotates keys — their call, not ours.
- **`.env` `IDP_ORG_ID`.** Points at the parent org (`e10ae12a…`); submit 404s there and
  succeeds against the business group that owns the action (`ef1232be…`). The user previously
  said "keep mine", before this evidence existed. W1.3 asks the design question underneath it:
  if access is per business group, is the org id part of *run identity* (ADR-0004 A8) rather
  than environment description?

## Explicitly NOT in this plan

- **Steps 1 and 2 of the target architecture** (headless service, version detection) stay
  blocked. W1.3 decides *which branch is live*, it does not build one. Nothing is implementable
  until that decision lands, and one option is "not feasible — stay with CI-on-PR".
- Re-raising the rigor profile to `standard`. Still owed before this tool gates another team,
  per `CLAUDE.md ## Rigor`, but it is a user decision and not blocking anything today.
