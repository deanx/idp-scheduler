# System invariants — cross-cutting functional properties

Properties no single story owns but the whole system must always hold — tenant isolation, referential integrity, "the ledger always balances", "every order has exactly one payment". Each has an executable check that runs at /qa for touched stories and system-wide at /signoff. A story that violates an invariant blocks Done. Curated by Soneca (/design).

| ID | Invariant (must always hold) | Why it matters | Check (test/assertion) | Scope (data/modules it spans) | Status |
|----|------------------------------|----------------|------------------------|-------------------------------|--------|
| INV-01 | Document files never enter the evaluation platform — only `document_id` + expected fields are stored. | Compliance design rule (`## Domain`): golden contents can carry PII/financial data; document files are a larger sensitive surface and the platforms have weak multimodal UI. Enforced in the adapter (file read for IDP submit only) and the platform adapter (writes only `document_id` + golden). | Assert no platform-write call payload contains file bytes or a file-path blob beyond `document_id`; assert `PlatformAdapter.write_scores` receives only `document_id` + golden + verdicts. | `adapter/`, `platform/`, golden storage | ⬜ PENDING |
| INV-02 | No credential and no golden-content value is ever logged in plain text. | Golden contents are sensitive (BR5); IDP client secret + platform API key are the auth surface (BR6). A debug log leaking a golden value or a token defeats the access control. | Static: gitleaks + a log-redaction unit test that feeds known PII/secret-shaped strings through the logging path and asserts they are redacted; runtime: assert no stdout/stderr in the test suite contains a golden field value. | `orchestration/`, `adapter/`, `platform/`, logging | ⬜ PENDING |
| INV-03 | Score names `field:<name>` and `gate` are a stable contract — never renamed without a versioned migration. | The remediation UI (Epic E) and any score-consuming downstream read these keys directly; a silent rename breaks them (Hyrum's Law, BR11). | Assert `PlatformAdapter.write_scores` always emits one score per golden field with key `field:<name>` and exactly one `gate` per document; contract test pins the key format. | `platform/`, `classifier/` (verdict→score mapping) | ⬜ PENDING |
| INV-04 | Every run records the action ID, action version and golden version used; no zero-exit run exists without all three. | Reproducibility (F16, BR10) — a run is only meaningful against a known version pair. ASM-03 (golden versioning) is app-tracked on Langfuse (ADR-0001), so the app must not silently skip recording it. | Assert every successful `run_eval` (exit 0) writes `action_id`, `action_version` and `golden_version` to run metadata; assert `action_version` comes from the required `--version` param (never a hard-coded constant or env var) and `action_id` from `--action` or its `IDP_ACTION_ID` default. | `orchestration/`, `platform/` (run metadata) | ⬜ PENDING |
| INV-05 | All credentials come from env/secrets; `load_dotenv()` is called before any SDK client is constructed. | Credentials must never live in code or committed config (BR6); constructing a client before env is loaded silently uses missing/empty creds. | Static: grep that no `Langfuse(` / SDK client construction appears before the `load_dotenv()` call in the entry script; unit test that monkeypatches env and asserts construction order. | `orchestration/`, `adapter/`, `platform/` | ⬜ PENDING |
| INV-06 | The orchestrator aborts the entire run on a per-document timeout or hard IDP failure — it never continues and never exits zero on a partial/failed run (ASM-02). | A partial run with a silent gap would produce a false-green CI gate — the run is either a complete reference (exit 0) or a failed run (non-zero), never a partial reference. | Assert each abort path (timeout, hard failure, auth failure, platform-write failure, empty golden set, dataset fetch failure, flush failure, unknown-status timeout) raises `RunAborted` and the CLI exits non-zero; assert no remaining documents are processed after an abort. | `orchestration/` | ⬜ PENDING |
| INV-07 | The poll/submit time budget uses a monotonic clock (`time.monotonic()` or an asyncio deadline), never `time.time()`. | A wall-clock budget can be corrupted by an NTP jump mid-poll — a negative jump could let a hung execution run far past its budget (false-green via timeout bypass) and a positive jump could abort a healthy execution. A monotonic clock is immune. | Assert the adapter's poll/submit deadline math uses `time.monotonic()` (static grep + a unit test that monkeypatches `time.time` and asserts it is not consulted for the budget). | `adapter/` | ⬜ PENDING |
| INV-08 | The gate result is computed BEFORE the platform write and is never inferred from what landed on the platform. | The platform is a record, not the source of truth for the gate. Inferring the gate from scores-on-the-platform would make a `write_scores` partial failure or a platform bug able to flip the CI signal — the gate must be a pure function of (golden, actual) computed in-process, then recorded. | Assert `overall_gate()` is called and its result captured before any `write_scores` call for that document; assert the exit-code aggregation reads the in-process gate, never a platform read-back. | `orchestration/`, `classifier/`, `platform/` | ⬜ PENDING |
